# 電卓アプリ 要件定義書

## 1. 文書情報

| 項目 | 内容 |
| --- | --- |
| 文書名 | 電卓アプリ 要件定義書 |
| 対象アプリ | Android 電卓アプリ |
| 初版 | 0.2.0 |
| 作成日 | 2026-09-04 |
| 対象OS | Android 7.0（API 24）以上 |

## 2. 背景・目的

日常的な四則演算を、起動後すぐに実行できるシンプルで視認性の高いAndroidアプリを提供する。入力内容と計算結果を明確に表示し、片手操作でも誤入力しにくい操作性を実現する。

本要件定義書では、最初のリリース（MVP）に必要な機能、画面、計算ルール、品質条件および受入条件を定める。

## 3. 対象範囲

### 3.1 対象（MVP）

- 数値入力（整数、小数）
- 加算、減算、乗算、除算
- 符号反転、パーセント、削除、全消去
- 計算結果の表示
- 連続計算
- 式および結果の表示領域
- ライトテーマ・ダークテーマ
- 端末の回転や再作成をまたいだ入力状態の維持

### 3.2 対象外（将来検討）

- 科学関数、関数電卓、単位変換
- 通貨換算やオンラインデータ取得
- 複数行の計算式編集
- ユーザーアカウント、クラウド同期
- 計算履歴の永続保存
- 広告、課金、外部サービス連携

## 4. 想定利用者・利用シナリオ

### 4.1 想定利用者

- 日常の買い物、割り勘、概算に使う一般ユーザー
- 特別な設定をせず、起動直後から計算したいユーザー

### 4.2 代表的なシナリオ

1. ユーザーがアプリを起動する。
2. 数値と演算子を入力する。
3. `=` を押して結果を確認する。
4. 必要に応じて結果を次の計算の先頭値として利用する。
5. `AC` で初期状態に戻す。

## 5. 機能要件

### FR-01. 数値入力

- `0`～`9` のボタンで数値を入力できる。
- `.` で小数を入力できる。同一の数値部分に複数の小数点は入力できない。
- 先頭の不要なゼロは正規化する。ただし `0.5` のような小数入力は可能とする。
- 入力中の数値と計算結果は画面上で確認できる。

### FR-02. 演算

- `+`、`−`、`×`、`÷` による四則演算を提供する。
- 演算子入力後に次の数値を入力できる。
- 演算子を連続して押した場合は、直前の演算子を最新の入力で置き換える。
- `=` を押すと現在の式を評価し、結果を表示する。
- `=` 実行後に数字を入力すると新しい計算を開始し、演算子を入力すると表示中の結果から計算を継続する。

### FR-03. 補助操作

- `AC` は入力中の式、結果、エラー状態を初期化する。
- `C` または削除操作は、入力中の数値の末尾を1文字削除する。入力が空の場合は何もしない。
- `±` は現在の数値の正負を反転する。
- `%` は現在の数値を100で割る（例: `50 %` → `0.5`）。

### FR-04. 表示

- 画面上部に、現在の式または直前の式を小さく表示する。
- 画面上部に、現在入力中の数値または計算結果を大きく表示する。
- 数値が画面幅を超える場合は、文字サイズを縮小するか横スクロールで全体を確認できる。
- 計算結果は不要な末尾のゼロを除いて表示する（例: `2.50` → `2.5`）。
- `-0` は表示せず `0` とする。

### FR-05. エラー処理

- 0除算を実行した場合は計算結果の代わりに「0で割ることはできません」などのエラーを表示する。
- エラー発生後に数字を入力すると新しい計算を開始できる。
- エラー発生後に `AC` を押すと通常の初期状態へ戻る。
- 数値の桁数や計算結果が扱える範囲を超えた場合は、アプリをクラッシュさせず「計算できません」と表示する。

### FR-06. 状態保持

- 画面再作成（回転、テーマ変更など）が発生しても、可能な範囲で式、入力値、結果、エラー状態を保持する。
- アプリを完全終了した場合の計算途中状態の永続化はMVPの対象外とする。

### FR-07. テーマ

- Material 3に基づくライトテーマとダークテーマを提供する。
- 初期状態は端末のシステム設定に追従する。
- テキストとボタンのコントラストを確保し、色だけに依存しない表示にする。

## 6. 画面要件

### 6.1 メイン画面

アプリ起動時に表示する唯一の画面とする。

| 領域 | 要件 |
| --- | --- |
| 式表示 | 入力済みの式、または直前に確定した式を表示する |
| 結果表示 | 現在値・計算結果を右寄せで表示する |
| 数字ボタン | `0`～`9`、`.` を配置する |
| 演算ボタン | `+`、`−`、`×`、`÷`、`=` を配置する |
| 補助ボタン | `AC`、削除、`±`、`%` を配置する |

- ボタンはタップ可能領域を十分に確保し、押下状態を視覚的に示す。
- 画面サイズや縦横向きにかかわらず、主要ボタンが画面外へ切れない。
- システムの戻る操作でアプリが予期せず終了しない。終了動作はAndroid標準挙動に従う。

## 7. 計算仕様

### 7.1 評価方式

- 入力された式は、通常の数学的な優先順位（乗算・除算を加算・減算より優先）で評価する。
- 同じ優先順位の演算子は左から右へ評価する。
- 括弧入力はMVPでは提供しない。
- 浮動小数点の表示誤差は、ユーザー表示時に不要な桁を整理する。

### 7.2 例

| 入力 | 表示結果 |
| --- | --- |
| `12 + 3 =` | `15` |
| `2 + 3 × 4 =` | `14` |
| `10 ÷ 4 =` | `2.5` |
| `50 %` | `0.5` |
| `5 ÷ 0 =` | 0除算エラー |

## 8. 非機能要件

### NFR-01. 性能

- ボタン操作から表示更新まで、通常時は体感遅延なく完了する。
- 計算処理はネットワーク接続を必要としない。
- アプリ起動後、メイン画面を操作可能な状態まで速やかに表示する。

### NFR-02. 安定性

- 不正な入力や計算エラーでクラッシュしない。
- 画面再作成後も状態が不整合にならない。
- Android API 24以上で動作する。

### NFR-03. アクセシビリティ

- すべての操作ボタンに内容が分かるアクセシビリティラベルを設定する。
- タップ領域、文字サイズ、コントラストをAndroidの一般的なアクセシビリティ指針に沿わせる。
- TalkBackで主要操作を識別できる。

### NFR-04. 保守性

- Kotlin、Jetpack Compose、Material 3を使用する。
- UI、状態管理、計算ロジックを分離し、計算ロジックを単体テスト可能にする。
- 既存プロジェクトのMVVM、Repository、Hilt、ktlint、detektの方針に適合させる。

### NFR-05. プライバシー

- 個人情報を収集しない。
- ネットワーク権限を要求しない。
- 計算内容を外部へ送信しない。

## 9. 技術・構成方針

- UI: Jetpack Compose + Material 3
- 言語: Kotlin
- 状態管理: ViewModel + StateFlow
- 計算エンジン: Androidフレームワークや外部サービスに依存しない純粋なKotlinロジック
- テスト: JUnitによる計算ロジックの単体テスト、Compose UIテストによる主要操作の検証
- 最小SDK: 24、Target SDK: 36

## 10. 受入条件

- [ ] `12 + 3 =` が `15` になる。
- [ ] `2 + 3 × 4 =` が `14` になる。
- [ ] 小数を含む計算が正しく表示される。
- [ ] 0除算でクラッシュせず、エラー内容が表示される。
- [ ] `AC`、削除、`±`、`%` が仕様どおりに動作する。
- [ ] `=` 後の連続計算ができる。
- [ ] 回転または画面再作成後に入力状態が失われない。
- [ ] ライトテーマ・ダークテーマの双方で文字とボタンを判別できる。
- [ ] Android API 24以上の対象環境でビルドできる。
- [ ] 単体テスト、UIテスト、Lintを実行できる。

## 11. 将来拡張候補

優先度と利用状況を確認したうえで、次の機能を検討する。

- 計算履歴の表示・削除
- 括弧、平方根、累乗などの科学計算
- 横画面での関数電卓レイアウト
- 結果のコピー・共有
- ユーザー設定による小数点以下の桁数指定
