## 2. 設計方針

- 起動直後に計算できる単一画面構成とする。
- UI、画面状態、計算ロジックを分離し、計算ロジックをAndroid環境に依存しない形で実装する。
- 入力途中の状態を明示的に管理し、不正な操作を黙って無視せず、ユーザーに分かる表示を行う。
- ネットワーク、ログイン、外部データベースに依存しない。
- Material 3の標準コンポーネントとテーマを使用し、ライト・ダークテーマの双方に対応する。

## 3. システム構成

### 3.1 論理構成

```text
ユーザー
  │ タップ
  ▼
CalculatorScreen（Compose UI）
  │ CalculatorAction
  ▼
CalculatorViewModel
  │
  ├── CalculatorEngine（式の評価）
  └── SavedStateHandle（画面再作成時の状態保持）
  │
  ▼
CalculatorUiState
  │ StateFlow
  └── CalculatorScreenへ再描画
```

### 3.2 採用アーキテクチャ

- MVVMを採用する。
- UIは`CalculatorUiState`を購読し、ユーザー操作を`CalculatorAction`としてViewModelへ渡す。
- ViewModelはUI状態を直接変更せず、計算エンジンの結果から新しい状態を生成する。
- 計算エンジンは純粋なKotlinクラスとし、単体テストで検証可能にする。
- MVPでは永続データがないためRepositoryは必須としない。将来履歴を追加する場合はRepositoryとRoomを導入する。

## 4. 画面設計

### 4.1 画面一覧

| 画面ID | 画面名 | 説明 |
| --- | --- | --- |
| CAL-001 | 電卓メイン画面 | 数値・演算子の入力、結果表示、補助操作を行う |

### 4.2 メイン画面レイアウト

```text
┌────────────────────────────┐
│ 式表示（右寄せ・小さめ）     │
│ 結果表示（右寄せ・大きめ）   │
├────────────────────────────┤
│ AC       DEL      %       ÷  │
│ 7        8        9       ×  │
│ 4        5        6       −  │
│ 1        2        3       ＋  │
│ ±        0        .       ＝  │
└────────────────────────────┘
```

- 画面全体を縦方向に配置し、表示領域とボタン領域を分ける。
- ボタン領域は均等なグリッドとする。
- `0`は必要に応じて2列分の幅を持たせるが、横画面や小さい端末でも切れない構成を優先する。
- 演算子と`=`は数字ボタンと区別できる色・形状とする。ただしコントラストとラベルで識別できることを前提とする。
- 式表示は入力式または確定済みの式、結果表示は現在値・結果・エラーを表示する。

### 4.3 操作イベント

| 操作 | ViewModelへ渡すイベント |
| --- | --- |
| 数字タップ | `DigitPressed(digit)` |
| 小数点タップ | `DecimalPressed` |
| 演算子タップ | `OperatorPressed(operator)` |
| `=`タップ | `EqualsPressed` |
| `AC`タップ | `AllClearPressed` |
| 削除タップ | `DeletePressed` |
| `±`タップ | `SignTogglePressed` |
| `%`タップ | `PercentPressed` |

## 5. 状態設計

### 5.1 UI状態

```text
CalculatorUiState
├── expression: String       // 式表示
├── displayValue: String     // 大きな結果表示
├── input: String             // 現在入力中の数値
├── tokens: List<Token>       // 評価待ちの式トークン
├── lastOperator: Operator?   // 直前の演算子
├── mode: CalculatorMode      // INPUT / RESULT / ERROR
└── errorMessage: String?     // エラー時のみ
```

- UIは原則として`displayValue`、`expression`、`mode`だけを表示に使用する。
- `input`と`tokens`は計算継続に必要な内部状態であり、画面再作成時に復元する。
- `mode`が`ERROR`の場合は、数字入力で新しい計算を開始し、`AC`で初期状態に戻す。

### 5.2 モード遷移

```text
INPUT ── "=" ──> RESULT
  │                │
  │ 演算子          │ 演算子
  ▼                ▼
INPUT            INPUT（結果を左辺に設定）
  │
  └─ 計算失敗 ──> ERROR ── AC ──> INPUT
                         └─ 数字 ──> INPUT
RESULT ── 数字 ──> INPUT（新規計算）
```

## 6. 計算仕様

### 6.1 トークン

入力式は次のトークンに分解する。

- `Number(value)`: 数値
- `Operator(type)`: `ADD`、`SUBTRACT`、`MULTIPLY`、`DIVIDE`

括弧、関数、変数はMVPでは扱わない。

### 6.2 評価方式

- 数値と演算子を左から読み取り、演算子の優先順位を考慮して評価する。
- 乗算・除算の優先順位を加算・減算より高くする。
- 同順位の演算子は左から右へ評価する。
- 結果は表示用フォーマッタを通して表示する。
- 0除算、非有限値、許容桁数超過は`CalculationError`として扱う。

### 6.3 数値表示

- 内部計算は`BigDecimal`相当の精度を優先し、丸め規則を一貫させる。
- 表示時は不要な末尾のゼロと小数点を除去する。
- `-0`は`0`に正規化する。
- 表示上限を超える場合は指数表記または計算エラーを選択する。MVPでは実装時に表示上限を固定する。

## 7. 状態保持・ライフサイクル

- ViewModelを画面単位で保持する。
- `SavedStateHandle`に`expression`、`displayValue`、`input`、`tokens`、`mode`を保存する。
- 画面再作成時は保存状態から`CalculatorUiState`を復元する。
- アプリのプロセス終了後も状態を永続化することはMVPの対象外とする。

## 8. テーマ・アクセシビリティ

- Material 3のカラースキームを使用する。
- システムのライト・ダーク設定を初期値として利用する。
- ボタンには表示文字と一致するcontent descriptionを設定する。
- タップ領域は最低48dpを確保する。
- 主要な表示と操作はTalkBackで意味が伝わる順序にする。

## 9. エラー方針

| エラー | UI表示 | 復帰操作 |
| --- | --- | --- |
| 0除算 | `0で割ることはできません` | 数字入力または`AC` |
| 数値範囲超過 | `計算できません` | `AC` |
| 不正な式 | `入力を確認してください` | `AC` |

- エラーはアプリ例外として画面外へ伝播させず、ドメイン結果としてViewModelで状態化する。
- エラー時もアプリは操作可能な状態を維持する。

## 10. テスト方針

- 計算エンジンの単体テストで、四則演算、優先順位、小数、0除算、境界値を検証する。
- ViewModelテストで各イベントと状態遷移を検証する。
- Compose UIテストで主要ボタンの表示、入力、結果表示、エラー表示を検証する。
- API 24相当以上のエミュレーターで起動、画面再作成、テーマ切替を確認する。

## 11. 将来拡張への配慮

- `Token`と評価器を独立させ、括弧・関数を追加できる構造にする。
- 計算結果をイベントとして扱い、履歴Repositoryを後から追加できるようにする。
- 画面を単一ActivityのCompose構成にし、将来の履歴画面追加に備える。
