## 3. 型定義

### 3.1 操作イベント

```kotlin
sealed interface CalculatorAction {
    data class DigitPressed(val digit: Int) : CalculatorAction
    data object DecimalPressed : CalculatorAction
    data class OperatorPressed(val operator: Operator) : CalculatorAction
    data object EqualsPressed : CalculatorAction
    data object AllClearPressed : CalculatorAction
    data object DeletePressed : CalculatorAction
    data object SignTogglePressed : CalculatorAction
    data object PercentPressed : CalculatorAction
}
```

`digit`は0～9だけを許可し、範囲外の値は呼び出し元のバグとしてテストで検出する。

### 3.2 演算子

```kotlin
enum class Operator(val symbol: String, val precedence: Int) {
    ADD("+", 1),
    SUBTRACT("−", 1),
    MULTIPLY("×", 2),
    DIVIDE("÷", 2)
}
```

### 3.3 トークン

```kotlin
sealed interface Token {
    data class Number(val value: BigDecimal) : Token
    data class OperatorToken(val operator: Operator) : Token
}
```

表示用の文字列と計算用の数値を分離し、浮動小数点の文字列解析に依存しない。

### 3.4 UI状態

```kotlin
data class CalculatorUiState(
    val expression: String = "",
    val displayValue: String = "0",
    val input: String = "0",
    val tokens: List<Token> = emptyList(),
    val mode: CalculatorMode = CalculatorMode.INPUT,
    val errorMessage: String? = null,
)

enum class CalculatorMode {
    INPUT,
    RESULT,
    ERROR,
}
```

## 4. CalculatorViewModel詳細

### 4.1 公開インターフェース

- `val uiState: StateFlow<CalculatorUiState>`
- `fun onAction(action: CalculatorAction)`

ViewModelはイベントを受け取って状態を1回だけ更新する。Compose側から内部状態を書き換えない。

### 4.2 イベント処理

| イベント | 処理 |
| --- | --- |
| `DigitPressed` | ERRORなら初期化して新規入力。RESULTなら新規入力。それ以外は現在値へ追加 |
| `DecimalPressed` | 現在の数値に`.`がなければ追加。`0`の場合は`0.`にする |
| `OperatorPressed` | 現在値をトークンへ確定し、演算子を追加。末尾演算子は置換 |
| `EqualsPressed` | 現在値をトークンへ確定し、Engineで評価してRESULTへ遷移 |
| `AllClearPressed` | 初期状態へ戻す |
| `DeletePressed` | 現在入力の末尾を削除。空になった場合は`0`にする |
| `SignTogglePressed` | 現在値の符号を反転。`0`は`0`のまま |
| `PercentPressed` | 現在値を100で除算し、表示値を更新 |

### 4.3 演算子連続入力

1. 現在入力を確定する。
2. `tokens`末尾が演算子なら、末尾を新しい演算子で置換する。
3. `tokens`末尾が数値なら、新しい演算子を追加する。
4. 次の数字入力時に`input`を`0`から開始する。

### 4.4 `=`後の継続

- RESULT中に数字を入力した場合、`tokens`を空にして新規計算を開始する。
- RESULT中に演算子を入力した場合、結果を最初の`Number`トークンとして次の式を開始する。
- RESULT中に`=`を押した場合は、直前の演算子と右辺を再利用する機能をMVPでは必須としない。必要になった時点で別要件として追加する。

## 5. CalculatorEngine詳細

### 5.1 API

```kotlin
class CalculatorEngine {
    fun evaluate(tokens: List<Token>): Result<BigDecimal>
}
```

### 5.2 入力検証

- 空のトークン列はエラーとする。
- 先頭・末尾が演算子の場合はエラーとする。
- 数値と演算子が交互でない場合はエラーとする。
- 数値は有限値であることを確認する。

### 5.3 評価アルゴリズム

Shunting-yard方式で演算子の優先順位を処理する。

1. `values`（数値スタック）と`operators`（演算子スタック）を用意する。
2. 数値は`values`へ積む。
3. 演算子を読む際、`operators`の末尾が同じか高い優先順位なら、先にその演算子を適用する。
4. 現在の演算子を`operators`へ積む。
5. 全トークン処理後、残った演算子を順に適用する。
6. `values`に結果が1つだけ残ることを確認する。

### 5.4 演算適用

```text
ADD      left + right
SUBTRACT left - right
MULTIPLY left * right
DIVIDE   left / right（right == 0 はエラー）
```

- 左辺と右辺はスタックから右辺、左辺の順に取り出す。
- 除算のスケールと丸めモードは実装時に固定値として定義し、テストで期待値を固定する。
- 演算途中で許容範囲を超えた場合は`CalculationException.OutOfRange`を返す。

## 6. CalculatorFormatter詳細

### 6.1 入力フォーマット

- 数字追加時は文字列として保持し、`BigDecimal`変換は演算確定時に行う。
- 先頭が`0`で小数点以外の数字を追加する場合、先頭の`0`を置き換える。
- `-`だけの状態は許可せず、符号反転は`-0`または`0`を適切に正規化する。

### 6.2 結果フォーマット

- `BigDecimal.stripTrailingZeros()`相当の処理で末尾のゼロを除く。
- 整数値は小数点を表示しない。
- `-0`は`0`へ変換する。
- 表示桁数が上限を超えた場合は`CalculationException.OutOfRange`とする。

## 7. Compose UI詳細

### 7.1 MainActivity

- `setContent`でアプリテーマを設定する。
- `CalculatorViewModel`を取得し、`collectAsStateWithLifecycle()`で状態を購読する。
- `CalculatorScreen(state, onAction)`だけを描画する。

### 7.2 CalculatorScreen

- `Scaffold`または同等のレイアウトで画面余白とシステムバーを考慮する。
- 上部に`CalculatorDisplay`、下部に`CalculatorKeypad`を配置する。
- `CalculatorUiState.mode == ERROR`の場合、結果表示領域に`errorMessage`を表示する。

### 7.3 CalculatorDisplay

- 式表示は`Text`を右寄せで表示する。
- 結果表示は大きい文字サイズで表示する。
- 長い文字列は縮小または横スクロールで確認可能にする。
- 表示専用Composableとして、状態変更や計算処理を持たせない。

### 7.4 CalculatorKeypad

- ボタン定義をリスト化し、同じレイアウト規則で描画する。
- 数字、演算子、補助操作をスタイルで区別する。
- 各ボタンに表示ラベル、アクセシビリティラベル、`CalculatorAction`を対応付ける。
- ボタンの押下時は`onAction`だけを呼び出す。

## 8. 状態保持

- `CalculatorUiState`はViewModelのスコープで保持する。
- 画面再作成（回転やテーマ変更）では同じViewModelが状態を保持する。
- プロセス終了後の計算途中状態の復元はMVPの対象外とする。

## 9. エラー定義

```kotlin
sealed class CalculationException : Exception() {
    data object DivisionByZero : CalculationException()
    data object InvalidExpression : CalculationException()
    data object OutOfRange : CalculationException()
}
```

ViewModelでは例外型をUIメッセージへ変換する。予期しないプログラムエラーを広範な`catch`で握りつぶさず、開発時に検出できるようにする。

## 10. テスト詳細

### 10.1 CalculatorEngine単体テスト

| 観点 | 例 |
| --- | --- |
| 基本演算 | `12 + 3 = 15`、`10 - 4 = 6` |
| 優先順位 | `2 + 3 × 4 = 14` |
| 左結合 | `20 ÷ 5 × 2 = 8` |
| 小数 | `10 ÷ 4 = 2.5` |
| 0除算 | `5 ÷ 0`がDivisionByZero |
| 不正式 | 演算子末尾、数値連続を拒否 |
| 境界値 | 0、負数、最大表示桁数 |

### 10.2 ViewModelテスト

- 数字入力、ゼロ正規化、小数点重複防止
- 演算子置換と連続入力
- `AC`、削除、符号反転、パーセント
- `=`後の新規計算・継続計算
- ERRORからの数字入力と`AC`復帰
- `SavedStateHandle`からの状態復元

### 10.3 UIテスト

- 主要ボタンが表示される。
- 数字と演算子をタップして期待結果が表示される。
- 0除算時のエラー表示を確認する。
- TalkBack用ラベルが設定されている。
- 縦横変更後も表示が崩れず、入力状態が維持される。

## 11. 実装時の確認事項

- 既存のパッケージ名、テーマ、依存関係の実態を確認してからファイルを追加する。
- 計算ロジックをCompose関数やActivityへ記述しない。
- `Double`の直接比較に依存せず、表示誤差と丸め規則をテストで固定する。
- 受入条件に対応するテスト名を付け、仕様変更時に文書とテストを同時に更新する。
