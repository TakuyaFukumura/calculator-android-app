# 計算履歴機能 仕様検討資料

## 1. 目的

計算結果を後から確認できるようにし、同じ計算の再確認や入力ミスの発見を容易にする。
本資料は、現在の電卓画面に計算履歴を追加する際の初期提案仕様である。

## 2. 前提と対象範囲

### 現状

- Jetpack Compose の単一電卓画面で、入力式と結果を表示している。
- 四則演算、`%`、符号反転、小数入力、削除、全消去に対応している。
- 計算状態は `CalculatorViewModel` のメモリ上に保持され、アプリ再起動後は復元されない。
- Room は既存の文字列データ用テーブルを使用している。

### 今回の対象

- `=` による計算成功時の履歴保存
- 履歴一覧の表示
- 履歴項目の選択による式の再利用
- 履歴の個別削除と全削除
- アプリ再起動後も履歴を保持する永続化

### 今回対象外

- 履歴の検索、並べ替え、カテゴリ分け
- 履歴のエクスポート・共有
- 複数ユーザーやアカウント単位の履歴
- 計算途中の入力や計算エラーの履歴保存

### 決定事項

| 項目 | 決定内容 |
| --- | --- |
| 表示形式 | モーダルの `ModalBottomSheet` |
| 履歴ボタン | 画面上部左側 |
| 履歴項目の再利用 | 式全体を電卓へ戻し、編集可能にする |
| 保存対象 | 成功した計算結果のみ |
| 保存件数 | 最大100件。超過時は古い履歴から削除 |
| 並び順 | 新しい履歴を上に表示 |
| 日時表示 | 表示しない。ただし並び順のため保存する |
| 削除 | 個別削除と全削除 |
| 永続化 | アプリ再起動後も復元 |

## 3. 提案するユーザー体験

### 3.1 履歴画面への導線

- 電卓画面の上部左側に「履歴」アイコンボタンを配置する。
- タップすると履歴一覧を表示する。
- 一覧はモーダル（`ModalBottomSheet` を第一候補）で表示し、閉じると電卓画面へ戻る。
- 履歴がない場合は「計算履歴はありません」と表示する。

### 3.2 履歴項目の表示

各項目を新しい順に表示する。1項目につき次を表示する。

```text
12 + 3 × 4
= 24
```

- 式は計算時の表示形式を保存する。
- 結果は `CalculatorFormatter` と同じ形式で表示する。
- 日時は表示しない。
- 長い式は一覧内で省略せず、横スクロールまたは複数行表示で確認できるようにする。

### 3.3 履歴項目の再利用

- 項目をタップすると、保存された式全体を電卓画面へ戻し、編集可能な状態にする。
- 式を編集してから `=` を押した場合は、編集後の計算結果を新しい履歴として保存する。
- 再利用後は履歴画面を閉じる。
- 履歴項目をタップしただけでは、新しい履歴として追加しない。
- 式の再利用後は、既存の電卓操作ルールに従って数字や演算子を編集する。

### 3.4 削除操作

- 項目の削除アイコンで個別削除する。
- 履歴画面の「すべて削除」で全削除する。
- 全削除は誤操作防止の確認ダイアログを表示する。
- 削除後に対象がなくなった場合は空状態を表示する。
- 削除失敗時は一覧を成功状態に見せかけず、エラーメッセージを表示する。

## 4. 保存仕様

### 4.1 保存タイミング

- `=` の計算が成功した直後に1件保存する。
- 計算エラー、未完成の式、`=` を押しても計算対象がない場合は保存しない。
- 同じ式を連続して計算した場合も、それぞれ別の履歴として保存する。
- 保存に失敗しても、計算結果の画面表示は維持する。履歴画面を開いた時点で失敗を通知できるようにする。

### 4.2 履歴の上限

- 保存件数の上限は **100件** とする。
- 101件目を保存する際は、最も古い項目を削除してから保存する。
- 上限値は将来変更できるよう、Repository または保存処理側の定数として一元管理する。

### 4.3 データモデル案

既存の文字列用テーブルとは分離し、`calculation_history` テーブルを追加する。

| カラム | 型 | 必須 | 内容 |
| --- | --- | --- | --- |
| `id` | `Long` | ○ | 自動採番された主キー |
| `expression` | `String` | ○ | 計算時の式（表示用） |
| `result` | `String` | ○ | 計算結果（表示用） |
| `createdAt` | `Long` | ○ | Epoch millis。新しい順表示と上限処理に使用 |

式と結果は、後から再計算して表示するのではなく、計算成功時の表示文字列を保存する。
これにより、将来の計算仕様や丸め規則が変わっても、過去の表示結果を維持できる。

### 4.4 データベース変更

- Room のデータベースバージョンを更新する。
- 既存の文字列データは削除・変換せず、そのまま保持する。
- 新規テーブル追加のマイグレーションを用意する。
- マイグレーションで既存利用者の履歴や既存データを失わない。

## 5. 状態管理と構成

既存の MVVM + Repository 構成を踏襲する。

```text
MainScreen
  ├─ CalculatorViewModel（入力・計算）
  └─ HistoryViewModel（一覧・削除・再利用）
       └─ CalculationHistoryRepository
            └─ CalculationHistoryDao
                 └─ Room: calculation_history
```

- DAO は `Flow<List<CalculationHistoryEntity>>` で新しい順の一覧を提供する。
- UI は `collectAsStateWithLifecycle` で一覧を購読する。
- DBアクセスは ViewModel の `viewModelScope` から非同期に実行する。
- 計算成功時の保存は Calculator 側から Repository を呼び出すか、履歴保存責務を持つユースケースへ委譲する。UIから直接DAOを呼び出さない。
- 履歴項目を選択した際は、保存した式をトークンへ再解析して編集可能な状態へ復元する。復元できない式は選択操作を失敗として通知し、履歴データは変更しない。

## 6. エラー・境界条件

| 条件 | 期待する動作 |
| --- | --- |
| 履歴0件 | 空状態を表示 |
| DB読み込み失敗 | エラー表示と再試行導線を表示 |
| 保存失敗 | 計算結果は表示し、履歴保存失敗を通知 |
| 個別削除失敗 | 項目を消えたように扱わず、エラーを通知 |
| 全削除失敗 | 確認ダイアログを閉じ、一覧を維持 |
| 100件超過 | 最古の項目から自動削除 |
| 非常に長い式・結果 | UIを崩さずスクロールまたは省略で表示 |
| 端末時刻の変更 | 保存済み `createdAt` を基準に並べ、表示時にローカル時刻へ変換 |
| 画面回転・プロセス再生成 | Roomから再取得して一覧を復元 |

## 7. アクセシビリティとUI要件

- 履歴ボタン、項目選択、個別削除、全削除に意味のある `contentDescription` を付ける。
- タップ可能な履歴項目は十分なタッチ領域を確保する。
- ダークテーマでも式・結果・エラーのコントラストを確保する。
- 結果の文字列だけでなく、式と結果の関係が読み上げで伝わる順序にする。

## 8. テスト観点

### 単体テスト

- 計算成功時に式・結果・日時が1件保存される。
- エラー計算では保存されない。
- 新しい順に並ぶ。
- 101件目の保存で最古の項目だけが削除され、100件を維持する。
- 個別削除、全削除が Repository から DAO に正しく伝播する。
- 空一覧と DB エラーが ViewModel の状態へ反映される。

### UI・結合テスト

- 履歴ボタンで一覧を開閉できる。
- 履歴項目をタップすると結果が電卓へ反映される。
- 全削除の確認をキャンセルすると履歴が残る。
- アプリ再起動後も保存済み履歴が表示される。
- ライトテーマ・ダークテーマ、長い式、空一覧でレイアウトが崩れない。

## 9. 実装ステップ案

1. `CalculationHistoryEntity`、DAO、Repository を追加する。
2. Room データベースにテーブルとマイグレーションを追加する。
3. 履歴の UI 状態と ViewModel を追加する。
4. 計算成功時の保存処理を Calculator と接続する。
5. 履歴ボタン、一覧、削除、確認ダイアログを Compose に追加する。
6. 項目選択による結果の再利用を接続する。
7. 単体テスト、UI テスト、マイグレーション確認を実施する。
